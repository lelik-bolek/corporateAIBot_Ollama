Проект MiNiFi являются частью экосистемы Apache, где NiFi предназначен для автоматизации передачи данных и обработки потоков данных, а MiNiFi является его облегченным вариантом, разработанным для устройств с ограниченными ресурсами.

Apache NiFi MiNiFi предоставляет следующие возможности: Небольшой размер и низкое потребление ресурсов Центральное управление агентами Создание истории (происхождения) данных с полной цепочкой управления информацией Интеграция с NiFi для последующего управления потоком данных MiNiFi функционирует в роли агента, действующего непосредственно рядом с исходными датчиками, системами или серверами.

Назначение/использование MiNiFi является легковесным агентом, разработанным Apache NiFi, который предоставляет возможность сбора данных и выполнения преобразований данных на удаленных устройствах или в периферийных средах. Он предназначен для использования в распределенных системах или на устройствах с ограниченными вычислительными ресурсами, таких как датчики, IoT-устройства или серверы в отдаленных местах.

MiNiFi агенты (развернутые экземпляры MiNiFi) работают на удаленных устройствах и выполняют задачи по сбору, фильтрации и передаче данных к центральной инфраструктуре Apache NiFi. Они могут собирать данные с различных источников, таких как файлы, сетевые порты, датчики и т. д. Агенты могут выполнять предварительную обработку и фильтрацию данных на периферии, чтобы уменьшить объем передаваемых данных и снизить нагрузку на сеть.

MiNiFi агенты также обеспечивают связь с серверами управления и контроля (C2 servers), которые управляют и координируют работой агентов. Серверы C2 предоставляют возможность удаленного управления и мониторинга агентов MiNiFi. Они могут отправлять команды агентам, контролировать их состояние, получать отчеты о сборе данных и принимать решения о дальнейших действиях.

Начало работы с MiNiFi Агент Java может запускать большинство доступных процессоров NiFi, но представляет собой более крупный двоичный дистрибутив (49 МБ) и потребляет больше системных ресурсов (максимальный размер JVM 24 МБ по умолчанию). Если вам нужна максимальная гибкость для принятия решений о маршрутизации и обработке в точке происхождения ваших данных, вам подойдет агент Java.

Агент C++ представляет собой двоичный файл меньшего размера (3,2 МБ), потребляет мало системной памяти (около 5 МБ в режиме ожидания), но имеет ограниченное подмножество процессоров. Если вашей основной задачей является сбор и отправка данных нижестоящим потребителям и минимизация воздействия на систему, агент C++ отлично подойдет.

Настройка NiFi для получения данных Во-первых, убедитесь, что в $NIFI_HOME/conf/nifi.properties указан порт входного сокета Site to Site: # Site to Site properties nifi.remote.input.host= nifi.remote.input.secure=false nifi.remote.input.socket.port=1026 nifi.remote.input.http.enabled=true nifi.remote.input.http.transaction.ttl=30 sec Перезапустите NiFi, чтобы изменения вступили в силу.

В веб-интерфейсе NiFi поместите входной порт «From MiNiFi» и подключите его к нижестоящему процессору: Создание потока MiNiFi Создайте новую группу процессов и дважды щелкните по ней, чтобы войти в нее. Работа внутри этой новой группы процессоров позволит нам создать чистый шаблон, включающий компоненты потока, предназначенные для работы в MiNiFi.

Внутри группы процессов создайте группу удаленных процессов (RPG) и дайте ей URL-адрес вашего экземпляра NiFi. RPG подключится к NiFi и обнаружит ранее созданный входной порт. Создайте обработчик TailFile и подключите его к RPG, выбрав входной порт «From MiNiFi».

Теперь создайте шаблон, загрузите его в виде XML-файла и загрузите Converter ToolKit. Из каталога набора инструментов: [user@host minifi-toolkit-0.0.1]#./bin/config.sh transform /path/to/template.xml /output/path/config.yml Java home: /usr/lib/jvm/jre-1.8.0-openjdk MiNiFi Toolkit home: /minifi-toolkit-0.0.1 No validation errors found in template.

Откройте файл config.yml и добавьте порт и хост в раздел «Свойства» в конце раздела «Входные порты» (в конце файла): Remote Processing Groups: - name: http://localhost:8080/nifi url: http://localhost:8080/nifi comment: '' timeout: 30 sec yield period: 10 sec Input Ports: - id: AUTOGENERATED_NIFI_PORT_ID_HERE name: MiNiFi-input comment: '' max concurrent tasks: 1 use compression: false Properties: # Deviates from spec and will later be removed when this is autonegotiated Port: 1026 Host Name: localhost Скопируйте сгенерированный файл config.yml в $MINIFI/conf/config.yml и запустите MiNiFi: [user@host nifi-minifi-cpp-0.1.0]#./bin/minifi.sh start Starting MiNiFi with PID 463 and pid file /nifi-minifi-cpp-0.1.0/bin/.minifi.pid Через несколько секунд вы должны увидеть, что NiFi получает данные на входной порт: Если вы не видите данных в очереди, возможно, они уже были использованы нижестоящим процессором (в данном случае PutFile). Если на входной порт вообще не поступают данные, проверьте файлы журналов MiNiFi и убедитесь, что файл, за которым ведется хвост, существует и не пуст.
