Жизненный цикл потоков Оглавление: Жизненный цикл потоков Разработка Тестирование Ввод в эксплуатацию Внесение изменений Вывод из эксплуатации Жизненный цикл потоков Для каждого потока обработки данных должен быть определен и соблюден единый жизненный цикл, включающий следующие этапы: 1. разработка; 2. тестирование; 3. ввод в эксплуатацию; 4. внесение изменений; 5. вывод из эксплуатации.

Разработка - Разработка ведётся в изолированном ландшафте. - Все логически завершённые изменения фиксируются в NiFi Registry. - Один коммит соответствует одной задаче или исправлению. Тестирование Детали по этапу тестирования в документе не раскрыты.

Ввод в эксплуатацию Перенос потока в вышестоящий ландшафт допускается только после: - завершения тестирования; - фиксации финальной версии в NiFi Registry; - указания версии, подлежащей развертыванию; - описания потока в информационной системе Заказчика.

Важно: в эксплуатацию переносится конкретная версия из Registry, а не «текущее состояние». Внесение изменений - Любые изменения в потоке, находящемся в эксплуатации, выполняются через создание новой версии в NiFi Registry. - Изменение потока без фиксации версии не допускается.

Вывод из эксплуатации - Перед выводом из эксплуатации фиксируется финальная версия потока. - Поток архивируется в Registry. - Указывается причина вывода. Все этапы жизненного цикла потока сопровождаются фиксацией изменений в NiFi Registry в соответствии с разделом «Управление версиями».
