Термины и определения Таблица 1. Термины Apache NiFi и технические сущности Термин Определение Apache NiFi Платформа потоковой обработки данных, используемая для построения, исполнения и мониторинга потоков обработки данных.

Back Pressure Механизм ограничения роста очередей FlowFile для предотвращения перегрузки и деградации потока. Concurrent Tasks Параметр процессора, определяющий количество параллельных потоков выполнения. Connection (Очередь) Связь между компонентами NiFi, по которой передаются FlowFile и в которой применяются механизмы Back Pressure.

Content (Тело FlowFile) Часть FlowFile, содержащая обрабатываемые данные, предназначенные для трансформации и передачи во внешние системы. Controller Service Служебный компонент NiFi, предоставляющий общую конфигурацию или подключение (например, к базе данных, схеме, SSL-контексту), которое может использоваться несколькими процессорами или другими сервисами без дублирования настроек.

Flow (Поток) Совокупность взаимосвязанных процессоров, групп процессов и связей, реализующих сквозную логику обработки данных в NiFi. FlowFile Базовая (основная и единственная) единица данных в NiFi, состоящая из тела сообщения (Content) и набора атрибутов (Attributes).

FlowFile Attributes (Атрибуты FlowFile) Часть FlowFile, содержащая набор метаданных, используемых для управления логикой обработки, маршрутизации, логирования и трассировки. Input Port Точка входа FlowFile в Process Group. NiFi Registry Система управления версиями потоков и Process Group.

Output Port Точка выхода FlowFile из Process Group. Parameter Context Механизм централизованного хранения конфигурационных параметров, включая Sensitive-значения. Process Group Логическая группа компонентов NiFi, предназначенная для изоляции, структурирования и повторного использования этапа обработки данных.

Processor Компонент NiFi, выполняющий конкретную операцию обработки данных над FlowFile. Relationships Вкладка «Отношения» содержит раздел «Автоматическое завершение/повторение отношений». Здесь перечислены все отношения, определенные процессором, вместе с их описанием, определяющие маршруты дальнейшей обработки FlowFile (Очереди).

Restricted Component Компонент NiFi с расширенными правами доступа к ресурсам хоста или возможностью выполнения стороннего кода. Обозначен значком щита. Более подробно здесь. Sensitive Property Параметр, содержащий чувствительные данные (пароли, токены), защищённый средствами NiFi.

Yield Механизм временной приостановки выполнения процессора после ошибки или неуспешной попытки обработки. Таблица 2. Архитектурные и методологические термины Термин Определение Бизнес-логика Правила и преобразования данных, обусловленные требованиями предметной области и целями обработки.

Временный сбой внешней системы Ошибка, вызванная кратковременной недоступностью или нестабильной работой внешнего источника или приёмника данных. Логический этап обработки Завершённый фрагмент обработки данных, реализующий конкретную бизнес-или техническую функцию и, как правило, оформленный в виде Process Group.

Локальность ответственности Принцип, согласно которому обработка данных, логирование и обработка ошибок ограничены пределами соответствующего логического этапа. Необрабатываемая ошибка выполнения Ошибка, при которой автоматическая обработка невозможна из-за несовместимости данных, бизнес-правил или конфигурации потока и требуется изменение логики либо решение Заказчика.

Ожидаемая ошибка данных Ошибка, обусловленная некорректными входными данными и не подлежащая повторной обработке без изменения данных. Пакетная модель выполнения Process Group Режим выполнения, при котором обработка одного набора FlowFile завершается полностью до начала обработки следующего набора.

Потоковая обработка Обработка FlowFile по мере их поступления без ожидания завершения обработки других данных. Приёмка потока Формальная проверка соответствия потока требованиям стандарта перед вводом в эксплуатацию. Сопровождаемость Способность потока быть понятым, изменённым и поддерживаемым без участия его автора.

Техническая логика Логика, обеспечивающая доставку, маршрутизацию, контроль, логирование и устойчивость обработки данных. Устойчивость потока Способность потока корректно работать при нагрузке, сбоях внешних систем и деградации отдельных компонентов.

Чувствительные данные Информация, несанкционированное раскрытие, изменение или использование которой может привести к рискам безопасности, финансовым потерям, нарушению законодательства или компрометации систем и пользователей.

Эталонный поток Пример потока, демонстрирующий корректное применение требований стандарта. Нет меток
