Чек-лист проверки потоков Оглавление: Введение Назначение Статус документа Порядок применения Ограничения Легенда критичности Чек-лист проверки потоков Apache NiFi Введение Настоящий чек-лист разработан в рамках Рекомендаций по проектированию потоков Apache NiFi и предназначен для оценки качества разработанных потоков обработки данных.

Назначение Чек-лист выполняет следующие функции: - Самопроверка разработчика — позволяет оценить соответствие потока принятым подходам перед передачей на тестирование или ревью - Унификация подхода — обеспечивает единые критерии оценки для всех участников процесса - Снижение рисков — помогает выявить потенциальные проблемы безопасности, производительности и сопровождаемости на ранних этапах Статус документа Документ имеет рекомендательный характер. Это означает, что: 1. Проверки, зафиксированные в чек-листе, отражают накопленный опыт и лучшие практики, но не являются безусловным требованием.

2. В случае противоречия между положениями чек-листа и требованиями Заказчика (техническое задание, архитектурные требования, политики безопасности, регламенты эксплуатации) приоритет имеют требования Заказчика. 3. Отступление от рекомендаций чек-листа допускается при наличии обоснования (техническая необходимость, ограничения инфраструктуры, специфика бизнес-логики) и документальной фиксации принятого решения.

Порядок применения Чек-лист применяется итеративно на следующих этапах жизненного цикла потока: Этап Участник Объём проверки Самопроверка Разработчик Все пункты (особое внимание — блокирующим и критическим) Code Review Tech Lead / Старший разработчик Подтверждение выполнения всех пунктов Приёмка в тестовой среде Тестировщик / Интегратор Проверки, связанные с тестируемостью, изоляцией сред, воспроизводимостью  Ограничения Чек-лист не заменяет: - Функциональное тестирование потока.

- Нагрузочное тестирование. - Проверки, специфичные для конкретного домена (финансы, медицина, промышленные данные и т.д.). Для таких случаев чек-лист может быть дополнен проектными или доменными проверками. Структура и визуальное оформление 1.1 Логическая структура Поток построен сверху вниз, ветвления — слева направо Схема читается как последовательный процесс; обратные связи не нарушают общей визуальной читаемости Рекомендательный 1.2 Группировка Крупные логические этапы выделены в Process Group Корневой уровень содержит только стартовые процессоры и Process Group; одиночные процессоры (кроме источников) на корневом уровне отсутствуют Рекомендательный 1.3 Размер Process Group Process Group не перегружена Если логический этап требует более 20–30 процессоров, рассмотреть декомпозицию; для < 3 процессоров отдельная PG не обязательна Рекомендательный 1.4 Цветовая маркировка Используется стандартная цветовая схема Жёлтый (`#ffff00`) — взаимодействие с внешними системами; синий (`#ade8ff`) — процессоры условий; красный (`#e32222`) — запись ошибок Рекомендательный 1.5 Комментарии Process Group содержит описание Заполнены комментарии для Process Group; для процессоров со сложной логикой (скрипты, нестандартные настройки) также добавлены пояснения; при необходимости используются Label Рекомендательный 2. Атрибуты и данные 3.1 Разделение content / attributes Техническая информация не вынесена в content, бизнес-данные — не в attributes Content содержит исходные и преобразованные бизнес данные; attributes — служебную информацию для маршрутизации, логирования, трассировки Критичный 3.2 Область действия атрибутов Атрибуты не передаются дальше, чем необходимо Атрибуты используются только внутри логического этапа; временные и диагностические атрибуты не выходят за пределы PG Рекомендательный 3.3 Удаление атрибутов Атрибуты удаляются после использования После использования атрибутов по назначению (кроме обязательных, п.

6.2.8) они удаляются Рекомендательный 3.4 Запрет на большие атрибуты Размер атрибутов ≤ 100 kB Отсутствуют атрибуты с объёмом более 100 kB; Критичный 3.5 Чувствительные данные Отсутствуют в открытом виде Пароли, токены, ключи не хранятся в attributes, комментариях, описаниях; вынесены в Parameter Context с типом Sensitive Блокирующий 4.
