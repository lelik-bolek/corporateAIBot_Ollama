# Спецификация RAG-пайплайна сервиса corporateAIBot_Ollama (v3)

## 1. Архитектурный обзор конвейера
Ядро пайплайна (`src/rag_pipeline.py`) реализует синхронно-асинхронную схему обработки запросов с локальным инференсом (ChromaDB + Ollama) и эшелонированной защитой на трёх рубежах.

```
              [Входящий HTTP-запрос /ask]
                          │
                          ▼
    ┌───────────────────────────────────────────┐
    │  Рубеж 1: Input Sanitizer                 │
    │  (Regex-проверка на прямые инъекции)      │
    └─────────────────────┬─────────────────────┘
             [Пройдено]   │   [Обнаружена атака]
        ┌─────────────────┴─────────────────┐
        ▼                                   ▼
┌─────────────────────────┐         ┌─────────────────────────┐
│ Этап 2: ChromaDB        │         │ Быстрый возврат:        │
│ Vector Search (Top-K)   │         │ SECURITY_BLOCKED_ANSWER │
└───────────┬─────────────┘         └─────────────────────────┘
			▼
┌─────────────────────────┐
│ Рубеж 2: Chunk          │
│ Sanitizer (Изоляция)    │
└───────────┬─────────────┘
			▼
┌─────────────────────────┐
│ Этап 3: Ollama          │
│ Инференс (qwen2.5:1.5b) │
└───────────┬─────────────┘
			▼
┌─────────────────────────┐
│ Рубеж 3: Output         │
│ Guardrail + Grounding   │
└───────────┬─────────────┘
			▼
┌─────────────────────────┐
│ Фоновое логирование:    │
│ FastAPI BackgroundTasks │
└─────────────────────────┘

```

## 2. Этапы выполнения конвейера

### Этап 1. Санитизация входа (Рубеж 1)
* Запрос проверяется по скомпилированным шаблонам `COMPILED_INJECTIONS` из `src/config.py`.
* При обнаружении прямой атаки генерация отменяется, возвращается стандартная заглушка безопасности, `llm_latency_ms` фиксируется как `0.0`.

### Этап 2. Векторный поиск (Retrieval & Score)
* Запрос векторизуется через `SentenceTransformer("intfloat/multilingual-e5-base")` с обязательным префиксом `query: `.
* Поиск в персистентной коллекции `ChromaDB` извлекает `TOP_K_CHUNKS` (по умолчанию 4) кандидатов.
* Вычисляется косинусное сходство (1.0 - {distance}). Если скор Top-1 чанка ниже `SIMILARITY_THRESHOLD = 0.80`, пайплайн инициирует регламентированный отказ без передачи контекста в LLM. (пример: 1.0 - {0.15} = 0.85)

### Этап 3. Санитизация и изоляция контекста (Рубеж 2)
* Функция `sanitize_context_chunks` отбрасывает чанки, содержащие маркеры непрямых инъекций или канарейки (умышленно добавлен файл с УЗ `poisoned_root.txt`).
* Оставшиеся фрагменты обрамляются изолирующими тегами `<КОНТЕКСТ>` в шаблоне `src/prompts/templates.py`.

### Этап 4. Локальная генерация (Ollama Inference)
* Модель: `qwen2.5:1.5b-instruct` через локальный C++ демон Ollama.
* Параметры: `temperature = 0.1`, `num_predict = 450`, `repeat_penalty = 1.15` (добавлен штраф за повторение. Если слово уже встречалось в тексте, его оценка делится на 1.15).
* Формат промпта: предписание краткого рассуждения (Chain-of-Thought) в 1–2 предложения и маркер `Ответ:`.

### Этап 5. Выходная фильтрация и верификация фактов (Рубеж 3)
- **Dual-Field Sanitizer:** Функция `sanitize_output` сканирует оба поля — `answer` и `chain_of_thought`. При выявлении маркеров канарейки (`swordfish`, учетных данных) рассуждение принудительно заменяется на `[Security Alert]: Внутреннее рассуждение скрыто...`.
- **Grounding Verification:** Флаг `is_known: true` выставляется только при одновременном соблюдении трёх условий:
  1. Top-1 скор сходства >= 0.80;
  2. Отсутствие фраз отказа (`REFUSAL_MARKERS`) в ответе;
  3. Доля пересечения значимых слов (длиной до 4х символов) ответа с контекстом составляет не менее 30% (`GROUNDING_OVERLAP_THRESHOLD = 0.30`).
