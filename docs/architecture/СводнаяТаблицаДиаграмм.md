# Итоговая сводная таблица всех диаграмм проекта

| № | Название схемы | Уровень C4 / Тип | Краткое назначение и ключевые элементы |
| --- | --- | --- | --- |
| **01** | **01 — C4 Container** | Container Diagram (Level 2) | Физические границы сервисов: контейнер FastAPI (`:8000`), контейнер Ollama (`:11434`), векторное хранилище ChromaDB (`chroma_db/`) и монтируемый том `logs/`.|
| **02** | **02 — C4 Component** | Component Diagram (Level 3) | Статическая декомпозиция модулей `src/bot.py`, `src/rag_pipeline.py`, источника настроек `src/config.py` и подсистемы **Security Perimeter** (`src/security/*`).|
| **03** | **03 — Dynamic Sequence** | C4 Dynamic / Sequence Diagram | Пошаговый сценарий прохождения запроса во времени: замер таймингов, ветвление **Fail-Fast** на 3 рубежах ИБ, сборка промпта и вызов Ollama.|
| **04** | **04 — Dual Logging Flow** | Data Flow Diagram | Разделение двух независимых потоков: синхронный аудит в `logs/system/app.log` и асинхронный сброс JSON Lines в `logs/eval/eval_runs_v3.jsonl` через `BackgroundTasks`.|
| **05** | **05 — Code Filters** | Code Diagram (Level 4) | Детализация функций модуля `src/security/filters.py`: регулярные выражения `COMPILED_INJECTIONS`, `COMPILED_LEAKS`, Dual-Sanitizer и Grounding-чекер ($30\%$ Overlap).|
| **06** | **06 — Code Pipeline** | Code Diagram (Level 4) | UML-представление классов `RAGPipeline`, `SecurityManager`, `EvalLogger`, их методов, типизации и Pydantic-моделей (`QueryRequest`, `QueryResponse`).|
| **07** | **07 — Offline Indexing** | ETL Data Flow | Офлайн-процесс подготовки данных: парсинг и чанкинг $800/150$, внешняя модель `intfloat/multilingual-e5-base`, запись векторов в `ChromaDB` и Smoke Test.|
