# ADR-002: Переход на гибридный поиск (Dense + BM25 + Reciprocal Rank Fusion) и миграция базы знаний на Apache NiFi

## Статус
Принято (Accepted)

## Контекст и проблематика
При миграции базы знаний с учебного стенда (изменённая вселенная Star Wars, 31 `.txt`) на корпоративные руководства по проектированию потоков Apache NiFi (15 PDF из Confluence) выявлена фундаментальная слепая зона чисто векторного поиска:

1. **Потеря точных идентификаторов:** Плотные эмбеддинги `intfloat/multilingual-e5-base` эффективно улавливают семантическую близость, но рассматривают уникальные буквенно-цифровые маркеры как шум. Имена процессоров (`GenerateFlowFile`, `PutDatabaseRecord`), параметры конфигурации (`Concurrent Tasks`, `Back Pressure`), порты, выражения NiFi Expression Language (`${UUID}`, `${filename}`) и коды системных ошибок терялись при чисто косинусном ранжировании.

2. **Специфика предметной области:** Документация Apache NiFi насыщена техническими терминами в CamelCase, табличными данными и точными значениями параметров, где критически важна точность совпадения, а не семантическая близость.

3. **Артефакты PDF-извлечения:** Исходные документы получены из Confluence в формате PDF и содержат специфичный мусор (мета-информация Confluence, URL `conf.ibs.ru`, колонтитулы с номерами страниц, бинарные иконки, разорванные многословные термины типа `Back\nPressure`), требующий дополнительного этапа очистки перед индексацией.
## Принятые решения

### 1. Внедрение BM25 (Sparse Retrieval)
- **Токенизация:** Реализована функция `tokenize_for_bm25()` в `src/build_index.py` с раздельной обработкой кириллицы (стемминг `SnowballStemmer("russian")`) и латиницы/спецсимволов (`.lower()` без искажения основы). Regex-паттерн: `[a-zA-Z0-9_\-\.\$]+|[а-яА-ЯёЁ]+`.
- **Индексация:** Разрежённый индекс `BM25Okapi` строится на том же корпусе чанков (800/150 через `RecursiveCharacterTextSplitter`) и сериализуется через `pickle` в `chroma_db/bm25_index.pkl` (~338 KB для 162 чанков).
- Ссылка: `src/build_index.py:82-103` (токенизация), `:175-203` (индексация).

### 2. Reciprocal Rank Fusion (RRF) с k=60
- **Dense:** ChromaDB + `multilingual-e5-base`, `TOP_K_DENSE = 5`.
- **Sparse:** BM25Okapi, `TOP_K_SPARSE = 5`.
- **Слияние:** RRF_Score(d) = sum(1/(60 + rank_m(d))) для m in {dense, sparse}.
- **Финальный отбор:** `FINAL_TOP_K = 3` чанков с наивысшим RRF-скором.
- Идентификация чанков между ветками — через глобальный индекс `chunk_N` из ID документа ChromaDB.
- Ссылка: `src/rag_pipeline.py:77-183`, `src/config.py:51-56`.

### 3. Миграция БЗ и нормализация
- Учебная БЗ Star Wars → `data/fictional_universe/`. Новая БЗ: 15 PDF из Confluence.
- Извлечение через `pypdf`, нормализация через `src/normalize_kb.py` с новой функцией `clean_confluence_artifacts()`.
- Канареечный файл `security_test_canary.txt` с 13 токенами.
- Ссылка: `src/normalize_kb.py:29-65`, `src/config.py:112-119`.

### 4. Телеметрия
- Поля `bm25_top_score` и `bm25_matches_count` в `eval_runs_v3.jsonl`.
- `retrieval_latency_ms` = суммарное время Dense + Sparse + RRF.
- `pipeline_params`: `top_k_dense`, `top_k_sparse`, `final_top_k`, `rrf_k`.
- Ссылка: `src/evaluation/logger.py:19-22,44-47`, `src/rag_pipeline.py:191-193,341-342`.

### 5. Промпты
- Шаблоны переведены на Apache NiFi: примеры с `FlowFile`, `Back Pressure`, `Controller Services`, `PutDatabaseRecord`.
- Ссылка: `src/prompts/templates.py:11-44`.

### 6. Зависимости и конфигурация
- `requirements.txt`: `pypdf>=4.0.0`, `rank-bm25>=0.2.2`, `nltk>=3.8.1`.
- `config.py`: `BM25_INDEX_PATH`, `TOP_K_DENSE=5`, `TOP_K_SPARSE=5`, `FINAL_TOP_K=3`, `RRF_K=60`, +6 LEAK_PATTERNS.

## Компромиссы и последствия

### Преимущества
- **Гарантированное нахождение точных терминов:** BM25 — 100% попадание по именам процессоров и параметрам.
- **Сохранение семантики:** Dense-ветка для синонимии и естественно-языковых запросов.
- **Низкие накладные расходы:** BM25 на CPU, RRF — O(N).

### Компромиссы
- **Двойное хранение:** ChromaDB + `bm25_index.pkl`, требуется синхронная переиндексация.
- **Ограничения pickle:** Индекс не переносим между версиями Python/платформами.
- **Связанность chunk_id:** При изменении чанкинга — согласованное обновление обеих частей.
- **Синхронная индексация:** Последовательное выполнение увеличивает время (компенсируется редкостью операции).
