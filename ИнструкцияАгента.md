# TASK: Implement Hybrid Search (BM25 + Dense + RRF) and KB Migration

## 1. Context & Goal
Текущий проект — локальный сервис `corporateAIBot_Ollama` (FastAPI, ChromaDB, multilingual-e5-base, Ollama qwen2.5:1.5b-instruct, Guardrails v3).
Цель: закрыть техдолг — устранить слепую зону семантического поиска по точным кодам и идентификаторам (имена процессоров, порты, параметры Apache NiFi) через добавление BM25 и Reciprocal Rank Fusion (RRF), а также перевести базу знаний с учебного стенда на 15 руководств по проектированию потоков Apache NiFi.

## 2. Reading Scope (Прочитать перед стартом)
Прочитай и зафиксируй логику следующих файлов проекта:
1. `src/config.py` — константы путей, пороги `SIMILARITY_THRESHOLD`, префиксы E5.
2. `src/build_index.py` — текущий цикл нарезки (800/150) и индексации в ChromaDB.
3. `src/rag_pipeline.py` — цепочка извлечения чанков, пороги, вызов LLM и замер `latency_ms`.
4. `src/security/filters.py` — правила `check_input_injection`, `sanitize_context_chunks`, `verify_grounding`.
5. `src/evaluation/logger.py` — формат записи JSONL в `logs/eval/eval_runs_v3.jsonl`.
6. `src/prompts/templates.py` — контекстная изоляция `<КОНТЕКСТ>` и правила генерации.

Критически важно: НЕ читай файлы из `data/`, `chroma_db/` и старые логи. Все пути реализуй через `pathlib.Path` для совместимости с Windows.

### Step 3. Dual Indexing (ChromaDB + BM25) based on `src/build_index.py`
1. Возьми за основу существующий проверенный скрипт `src/build_index.py`.
2. Сохрани без изменений текущий алгоритм чанкинга (`load_and_chunk_documents` с `RecursiveCharacterTextSplitter`, размер окна 800, перекрытие 150) и логику записи плотных векторов E5 в ChromaDB (`metadata={"hnsw:space": "cosine"}`).
3. Добавь в этот же скрипт функцию подготовки токенов для BM25:
   - `tokenize_for_bm25(text: str) -> list[str]`:
     - Выделение токенов regex-паттерном `r"[a-zA-Z0-9_\-\.\$]+|[а-яА-ЯёЁ]+"`.
     - Кириллические токены обрабатывай `nltk.stem.snowball.SnowballStemmer("russian")`.
     - Латиницу, спецсимволы и цифры приводи к `.lower()` без искажения основы.
4. Дополни функцию `build_and_save_index()` формированием разрежённого индекса:
   - Для сформированных чанков подготовь токенизированный корпус через `tokenize_for_bm25`.
   - Инициализируй `BM25Okapi(tokenized_corpus)`.
   - Сериализуй и сохрани объект {"bm25": bm25_instance, "chunks": [{"chunk_id": str(i), "text": doc.page_content, "source_file": doc.metadata["source"]} for i, doc in enumerate(chunks)]} через pickle в BM25_INDEX_PATH.
*Acceptance Criteria:* Скрипт `python -m src.build_index` успешно выполняется, наполняет коллекцию в `chroma_db/` и создаёт валидный файл `chroma_db/bm25_index.pkl`.

> 🛑 **СТОП-ТОЧКА Step 3**

### Step 4. Hybrid Retrieval & RRF Pipeline (`src/rag_pipeline.py`)
1. В `__init__` класса `RAGPipeline` загрузи `bm25_index.pkl` в память.
2. В методе извлечения контекста реализуй две ветки:
   - **Dense:** получение `TOP_K_DENSE` чанков из ChromaDB.
   - **Sparse:** токенизация вопроса через `tokenize_for_bm25` -> `bm25.get_scores()` -> выбор `TOP_K_SPARSE` чанков.
3. Реализуй слияние:
   $$\text{RRF\_Score}(d) = \sum_{m \in \{\text{dense}, \text{sparse}\}} \frac{1}{\text{RRF\_K} + \text{rank}_m(d)}$$
4. Отбери `FINAL_TOP_K` чанков с наивысшим `RRF_Score`.
5. Обнови `src/prompts/templates.py`: замени Few-Shot примеры Aetheria/Star Wars на примеры с терминами NiFi (FlowFile, Backpressure, Controller Services).
*Acceptance Criteria:* Пайплайн при запросе с точным именем процессора (например, `PutDatabaseRecord`) возвращает релевантный чанк даже при низком ранге в Dense-поиске.

> 🛑 **СТОП-ТОЧКА Step 4**
